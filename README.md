# Enterprise AI Personalized Dashboard

A production-quality hackathon project demonstrating:

- **Personalization in enterprise applications** — every employee sees a dashboard tailored to their role, workload, and context
- **AI-driven employee experience** — LLM-powered recommendations, chat, email drafting, and productivity summaries
- **Scalable AI integration** — LiteLLM provider-agnostic layer; switch between OpenAI, Anthropic, Groq, Gemini, IBM watsonx.ai, or Ollama by changing one environment variable

## Setup & Run

### Prerequisites

- Python 3.11+
- Node.js 20+
- An API key for at least one LiteLLM-supported provider

---

### Backend

```bash
cd amadeus-dashboard/backend

# Create and activate a virtual environment
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt

# Configure environment
cp .env.example .env
# Edit .env — set MODEL and the API key for your chosen provider

# Start the API server
uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

API docs available at: http://127.0.0.1:8000/docs

---

### Frontend

```bash
cd amadeus-dashboard/frontend

# Install dependencies
npm install

# Start the dev server
npm run dev
```

App available at: http://localhost:5173

---

### Docker (full stack)

```bash
# Copy and configure your .env
cp amadeus-dashboard/backend/.env.example amadeus-dashboard/backend/.env
# Edit .env with your API keys

docker compose -f amadeus-dashboard/docker-compose.yml up --build
```

Frontend: http://localhost:3000  
Backend API: http://localhost:8000

## Environment Variables

| Variable | Description |
|---|---|
| `MODEL` | LiteLLM model string (e.g. `gpt-4o-mini`) |
| `OPENAI_API_KEY` | OpenAI API key |
| `GROQ_API_KEY` | Groq API key |
| `GEMINI_API_KEY` | Google Gemini API key |
| `ANTHROPIC_API_KEY` | Anthropic API key |
| `AZURE_API_KEY` | Azure OpenAI API key |
| `AZURE_API_BASE` | Azure OpenAI endpoint URL |
| `AZURE_API_VERSION` | Azure OpenAI API version |
| `WATSONX_API_KEY` | IBM watsonx.ai API key |
| `WATSONX_URL` | IBM watsonx.ai service URL |
| `WATSONX_PROJECT_ID` | IBM watsonx.ai project ID |

### Supported Model Examples

```bash
# OpenAI
MODEL=gpt-4o-mini

# Groq (fast, free tier)
MODEL=groq/llama3-8b-8192

# Anthropic
MODEL=anthropic/claude-3-haiku-20240307

# Google Gemini
MODEL=gemini/gemini-1.5-flash

# Azure OpenAI
MODEL=azure/gpt-4o

# IBM watsonx.ai
MODEL=watsonx/ibm/granite-13b-chat-v2

# Ollama (local)
MODEL=ollama/llama3
```

## Features

- **Personalized dashboard** — each user sees their own tickets, PRs, meetings, escalations, and sprint
- **AI Recommendations** — 5 prioritized, context-aware recommendations generated by the LLM
- **AI Chat** — conversational assistant with the full employee profile injected as context
- **Email Generator** — draft customer emails, status updates, meeting summaries, and sprint updates
- **AI Summary** — daily productivity analysis with risk level, workload estimate, and motivational message
- **User switcher** — switch between 4 employee personas in the sidebar
- **Radar chart** — visual work health score across 5 dimensions
- **Dark mode glassmorphism UI** — production-quality design

## Security Notes

- API keys are loaded from environment variables only — never hardcoded
- CORS is restricted to configured origins
- Backend binds to `127.0.0.1` (not `0.0.0.0`) for local dev
- Docker images use Red Hat UBI minimal base with non-root user
